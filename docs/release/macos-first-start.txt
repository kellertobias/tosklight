ToskLight for macOS - first start
=================================

Releases built with Apple distribution credentials are Developer ID signed and notarized.
Testing builds made without these credentials are ad-hoc signed.

1. Expand the ZIP and move the application you want to use to Applications.
2. Open the application. If macOS blocks a testing build, check that this archive came from the
   expected GitHub release. Open System Settings > Privacy & Security, choose Open Anyway for
   the application, and confirm Open. On macOS Sequoia and later, Control-click does not bypass
   this approval.

Optional local signing for testing builds
----------------------------------------

In Terminal, change into the expanded bundle and run:

  cd /path/to/tosklight-bundle-macos_arm64
  bash sign-macos-apps-locally.sh

For an individual app, pass its path instead:

  bash sign-macos-apps-locally.sh "/Applications/ToskLight.app"

The script recognizes Control, Architect, Pixel, and Hardware Controls when present. It keeps
verified Developer ID signatures and applies local ad-hoc signatures to testing builds, including
their helpers. It does not remove download quarantine or disable Gatekeeper. Local signing does
not replace the Open Anyway approval. To undo local signing, replace the app with a fresh download.

If signing or verification fails, verify the archive against report-checksums.txt and download a
fresh release. Do not bypass an invalid-signature or damaged-application error.

Pixel media import requires separately installed, working ffmpeg and ffprobe executables. They
are not included in these downloads. A successful startup does not prove media import is available.
