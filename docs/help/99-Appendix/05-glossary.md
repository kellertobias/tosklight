# Glossary

| Term | Meaning in ToskLight |
| --- | --- |
| Fixture | A logical show object with a profile, mode, identity, and placement. It remains in the show when unpatched. |
| Head | An independently selectable part of a fixture. A `.0` master holds shared attributes; `.1` onward identify child heads. |
| Split | An independently patched address block within one fixture mode. |
| Multi-patch | Additional physical copies of one logical fixture, sharing its programming. |
| Programmer | The desk's shared temporary selection and values, which become stored programming when recorded or updated. |
| Command line | The programmer command entry for fixture selections and desk operations. |
| Group | A reusable ordered fixture selection. Its order can affect spreads and Dynamics. |
| Preset | Reusable attribute values recalled into the Programmer. |
| Cue | Stored programming and timing within a Cuelist. |
| Cuelist | An ordered set of Cues with playback and tracking behavior. |
| Tracking | Values carried through later Cues until changed or released. Live performer tracking is described separately under PosiStageNet. |
| Playback | A control assigned to a Cuelist, Group master, Dynamic, Macro, or another supported function. |
| Dynamic | Reusable animated attribute programming with lanes, phase, and speed. |
| Preload | Pending changes held for inspection before Preload GO applies them. |
| Desktop | A saved arrangement of panes on a Control screen. |
| Visualizer | The lighting renderer used with Architect and Control. Pixel's generated visuals are media sources. |
| GDTF | A fixture-description archive imported into the fixture library. |
| MVR | Rig interchange carrying fixture and placement data. Keep native `.show` files for programming and recovery. |
